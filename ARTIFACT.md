# Replication package

Artifacts for *Unveiling Discrepancies in Android App Data Safety Declarations
and Privacy Policies: An In-depth Analysis using Large Language Models*.

This package exists because Reviewer 1 asked (Major Issue 5) which research
artifacts are available and whether they suffice to reproduce the reported
results. It answers that question in both directions: it provides everything
needed to reproduce the analyses added in the revision, and it states plainly
what from the original 2024 runs did not survive.

---

## 1. What can and cannot be reproduced

### Fully reproducible

| Claim in the paper | Regenerated by |
|---|---|
| Confusion matrices behind all eight published cases | `analysis/scripts/01_reconstruct_confusion.py` |
| Prevalence-aware re-analysis, degenerate-classifier finding, threshold-shift test | `analysis/scripts/02_error_analysis.py` |
| Inter-annotator agreement and the difficulty analysis | `analysis/scripts/03_annotator_reliability.py` |
| Qualitative discrepancy cases | `analysis/scripts/04_qualitative_examples.py` |
| Corpus defect prevalence and difficulty predictors | `analysis/scripts/05_corpus_prevalence.py` |
| Empirical resolution of the label-direction contradiction | `analysis/scripts/06_verify_label_semantics.py` |
| Discrepancy pattern taxonomy | `analysis/scripts/07_discrepancy_taxonomy.py` |
| Current-generation validation and hallucination probes | `artifact/replication/` (see §3) |

These scripts read only the published corpus and the published metrics. They
require Python 3.9+ and, for the corpus analyses, `pandas` and `scikit-learn`.
They are deterministic.

### Not reproducible, and why

The fine-tuning driver scripts and the per-app prediction files for the eight
original cases were committed to the project repository as **zero-byte files**,
and no other copy exists. Consequently:

- the eight original runs **cannot be re-executed as they were run**;
- the original per-app predictions **cannot be inspected directly** (which is why
  the confusion matrices are recovered algebraically instead);
- fine-tuning **hyperparameters were not logged**. The base model is recorded as
  `gpt-3.5-turbo-0613` and the hosted service's defaults were used, but those
  defaults were provider-chosen per job and are not retrievable now.

Exact snapshot identifiers for the GPT-4, GPT-4o and Gemini 1.5 endpoints used
for label generation were likewise not recorded. We do not reconstruct values we
cannot evidence. The replication harness in §3 was written so that future runs
do not have this problem: it records the resolved model identifier the provider
returns, every decoding parameter, and every raw response.

4,866 rationales) is distributed as the companion data package, with its own
codebook, field dictionary and SHA-256 manifest.

## 3. Reproducing the model experiments

### 3.1 Build the evaluation and probe sets

```bash
cd artifact/replication
python3 build_eval_set.py          # -> data/eval_set_natural.csv, eval_set_balanced.csv
python3 make_probes.py             # -> data/probe_null.csv, probe_inject.csv, probe_shuffle.csv
```

`build_eval_set.py` keeps only apps whose annotators agreed, requires both
documents to be present, stratifies by Google Play category, and writes a
manifest recording the realised class priors, the derivation rule for each
target, the seed and file checksums.

The resulting 300-app set has a near-balanced prior (0.54 `Incorrect`, 0.58
`Incomplete`). This is deliberate: the original 150-app test set was 0.913 and
0.807, at which a classifier that flags everything already scores 0.91 and 0.81
accuracy.

**Probe reference answers are fixed by construction, not by annotation:**

| Probe | Construction | Reference | A violation means |
|---|---|---|---|
| `null` | policy replaced by a contentless placeholder | `incorrect = 0` | the model asserted policy content that is absent |
| `inject` | one explicit undeclared disclosure appended to the real policy | `incorrect = 1` | the model ignored evidence present in its input |
| `shuffle` | policy sentences reordered | labels unchanged | the verdict is unstable, not reasoned |

### 3.2 Run a model

```bash
export OPENAI_API_KEY=sk-...          # or ANTHROPIC_API_KEY / GEMINI_API_KEY

python3 run_benchmark.py --provider openai --model <model> \
    --dataset data/eval_set_natural.csv --tag base    --out runs/
python3 run_benchmark.py --provider openai --model <model> \
    --dataset data/probe_null.csv      --tag null     --out runs/
python3 run_benchmark.py --provider openai --model <model> \
    --dataset data/probe_inject.csv    --tag inject   --out runs/
python3 run_benchmark.py --provider openai --model <model> \
    --dataset data/probe_shuffle.csv   --tag shuffle  --out runs/

# self-consistency: identical prompts, repeated
python3 run_benchmark.py --provider openai --model <model> \
    --dataset data/eval_set_natural.csv --tag rep \
    --repeats 3 --temperature 0.7 --limit 100 --out runs/
```

No API account is needed to reproduce the pipeline end to end: the same commands
run against a local model by passing `--provider ollama --model <name>`. The
harness depends only on the Python standard library, so there is no dependency
resolution to reproduce.

The filename tag matters — `score.py` and `make_result_tables.py` discover runs
by it.

### 3.3 Score and build the tables

```bash
python3 score.py runs/*base*.jsonl
python3 measure_hallucination.py \
    --base runs/*base*.jsonl --null runs/*null*.jsonl \
    --inject runs/*inject*.jsonl --shuffle runs/*shuffle*.jsonl \
    --repeats runs/*rep*.jsonl --label "<model>"
python3 make_result_tables.py --runs runs --out ../../manuscript/tables
```

Unparsed responses are never silently dropped. `score.py` takes an explicit
`--unparsed {exclude,negative,positive}` policy and reports the coverage loss
either way.

### 3.4 Regenerate the analysis tables

```bash
cd analysis/scripts
for s in 0*.py; do python3 "$s"; done
cp ../results/table_*.tex ../results/examples_*.tex ../../manuscript/tables/
```

## 4. Honest notes on determinism

Inference against a hosted model is not bit-reproducible even at temperature 0:
providers change model weights behind a stable alias, apply non-deterministic
batching, and may alter defaults without notice. We therefore report the decoding
parameters, the number of repeats and the **measured** self-consistency rather
than claiming determinism.

Two further caveats apply to the original corpus and are stated in the paper:

1. The privacy-policy text in the corpus is **not raw policy text**. It was
   condensed by GPT-4 into `Data Share:` / `Data Collect:` sections before any
   classification, at a decoding temperature that was not fixed. That stage is
   therefore non-deterministic, and in the GPT-4-labelled cases the same model
   family both condensed the evidence and produced the labels.
2. The direction of the `Incorrect` label was stated inconsistently across the
   original manuscript and code. It is resolved empirically in
   `06_verify_label_semantics.py`; the direction of `Incomplete` could **not** be
   resolved from the corpus, and results on that dimension should be treated as
   weaker evidence.

## 5. Licensing and ethics

Code is released under a permissive licence; the corpus under an open-data
licence. Annotator identifiers are pseudonymised (`A01`–`A07`) and account
credentials are excluded from the distribution.

The app-level findings document mismatches between two **disclosure artefacts**.
They are not measurements of runtime behaviour and not allegations of
intentional wrongdoing. Anyone reusing the named cases should preserve that
framing.
